# 認知的負荷・タイピング動態収集アプリ (Cognitive Load & Keystroke Dynamics Collector)

## 1. アプリの目的と概要
このアプリケーションは、PCでの**タイピング動態（キーストローク：キーを押した・離したタイミング）**と、Bluetooth心拍センサー（Polar Verity Sense等）から取得する**心拍間隔データ（PPI）**を、同じPC時計の上で同期して記録するための実験用ソフトウェアです。

被験者に3段階の認知負荷（写経のみ／写経＋音声の数字カウント）を与え、その際のタイピングの変化、主観的負荷（NASA-TLX）、副課題成績、自律神経の反応（心拍変動）を収集します。

収集したデータは `master_analysis` リポジトリで解析します。研究の主目的は、タイピングに含まれる被験者固有情報を抑制することで、**未知被験者に対する認知負荷推定性能を改善できるか**を検証することです。

### 💡 なぜ「LSL (Lab Streaming Layer)」を使っているのか？（重要）
通常、キーボードの入力とBluetoothの心拍データを別々のプログラムで保存すると、OSの処理遅延やBluetoothの通信の揺らぎにより、必ず「時間のズレ（同期ズレ）」が発生します。
本アプリでは、LSLという生体信号同期用のネットワーク技術を用いています。中継器がBluetoothデータをLSLネットワークに放流し、メインアプリがそれを受信した瞬間に、**「キーボード入力と全く同じPC内蔵の高精度時計」**でタイムスタンプを打刻します。

ただし、Polarは約5秒ごとにデータをまとめて送信するため、記録される心拍の `Timestamp` は「PCが受信した時刻」であり、実際の拍動時刻より最大約5秒遅れます。実際の拍動時刻は、解析時に `master_analysis` の Global Anchor 方式（PPIの累積和から逆算）で復元します。

## 2. システム要件と必須ライブラリ

実行環境: Python 3.9 以上

依存関係がシステム全体に影響を与えないよう、**仮想環境（.venv）**を作成して実行することを強く推奨します。以下の手順でセットアップしてください。

```bash
# 1. 仮想環境の作成
python -m venv .venv

# 2. 仮想環境のアクティベート（有効化）
# 【Windowsの場合】
.\.venv\Scripts\activate
# 【Mac/Linuxの場合】
source .venv/bin/activate

# 3. 必要なライブラリの一括インストール（必ずアクティベートした状態で実行）
pip install -r requirements.txt
# または
pip install PySide6 pylsl pygame bleak pandas matplotlib pynput
```
※ターミナルの行頭に `(.venv)` と表示されていれば、正しく仮想環境が有効化されています。以降は単に `python main.py` と打つだけで仮想環境のPythonが実行されます。

## 3. 実験の実施手順（使い方）

### Step 1: 心拍センサーの装着
センサーは**胸部（利き手と逆側の鎖骨の中心から指2〜3本分下の平らな部分）**に装着します。腕や手首への装着は、タイピングの体動ノイズでHRVが計測できなくなるため使いません。センサーの光学面を直接肌に当て、キネシオロジーテープ2枚を「✕」または「＋」の形に交差させて固定・遮光します。

### Step 2: 心拍センサー中継器の起動
センサーの緑色のLEDが点灯している（脈を検知している）ことを確認してから、ターミナルで以下を実行します。

```bash
python polar_to_lsl.py
```
出力例：
```text
[INFO] Polarデバイスをスキャン中...
[SUCCESS] Polarデバイスに接続しました！
[DATA] 送信中: 850.5 ms (HR: 70 BPM)
```
このように `[DATA]` が流れ始めたら準備完了です。このターミナルは**開いたまま（裏で動かしたまま）**にしておきます。
*(※手元にPolarデバイスがない場合は、代わりに `python lsl_mock.py` を起動すればテストが可能です)*

### Step 3: メインアプリの起動
**別の新しいターミナルを開き**、メインアプリを起動します。

```bash
python main.py
```
- 起動ダイアログで「被験者 ID」（例：`N05`）を入力します。この名前がデータフォルダ名とファイル名になります。
- 同じダイアログで「プロトコルパターン」を1〜9から選択します（上表の割付表に従う）。
- 自動的に裏で動いているLSLストリームを見つけ出し、実験画面が開きます。
- あとは画面の指示と自動タイマーに従って、被験者にタスクを進めてもらいます。
- 最後の「終了画面」が出た瞬間に、すべてのデータが `data/{ID}/` フォルダにCSVとして一括保存されます。

## 4. 出力されるCSVデータの見方
実験完了後、`data/{ID}/` フォルダに以下のCSVファイルが生成されます。

### ① `keystrokes_{ID}.csv`（タイピング動態ログ）
| Timestamp | EventType | KeyCode | Char | Current_Phase |
|-----------|-----------|---------|------|---------------|
| 12345.678 | KeyDown   | 65      | a    | Task 1: Low (Text A) |
| 12345.750 | KeyUp     | 65      | a    | Task 1: Low (Text A) |
* **意味**：キーボード入力の開始と終了を時系列で記録します。`Timestamp` はアプリ内部で使う同一時計の秒単位タイムスタンプです。`Current_Phase` 列には、そのタイピングがどのフェーズ中に行われたかが記録されます。
* **分析用途**：KeyDown→KeyUpの差分から「滞空時間（Dwell Time）」を、KeyUp→次のKeyDownの差分から「キー間時間（Flight Time / IKI）」を算出できます。

### ② `heartrate_{ID}.csv`（心拍間隔・PPIデータ）
| Timestamp | PPI | Current_Phase |
|-----------|-----|---------------|
| 12345.800 | 850 | Task 1: Low (Text A) |
| 12346.660 | 860 | Task 1: Low (Text A) |
* **意味**：PPIは心拍同士の間隔（ミリ秒）です。`Timestamp` と `Current_Phase` はPCが**受信した時点**の値であり、バッチ送信のラグ（最大約5秒）を含みます。
* **分析用途**：`master_analysis` で実際の拍動時刻（`True_Timestamp`）と、その時刻に基づくフェーズ（`True_Phase`）を復元したうえで、RMSSDなどのHRV指標を算出します。

### ③ `events_{ID}.csv`（イベントマーカー）
| Timestamp | EventName |
|-----------|-----------|
| 12300.000 | 開始: Task 1: Low (Text A) |
| 12480.000 | 終了: Task 1: Low (Text A) |
| 12510.000 | 提出: Survey after Task 1 |
* **意味**：各フェーズの開始（`開始:`）、終了（`終了:`）、アンケート提出（`提出:`）の時刻を記録したデータです。
* **分析用途**：keystrokes / heartrate の連続データを、各フェーズごとに切り出すために使います。

### ④ `surveys_{ID}.csv`（タスク後アンケート）
| TaskName | UserInputCount_1 | UserInputCount_2 | MentalDemand | PhysicalDemand | TemporalDemand | Performance | Effort | Frustration |
|----------|------------------|------------------|---|---|---|---|---|---|
| Task 2: Medium (Text B) | 12 | | 7 | 6 | 4 | 3 | 4 | 4 |
* **意味**：各タスク後に回答したNASA-TLX（0〜10の11段階）と、音声タスクで入力したカウント数です。行はタスクの実施順に並びます。
* **カウント列**：低負荷では両方とも空欄です。中負荷では「7」の個数（`UserInputCount_1`）、高負荷では「1」の個数（`UserInputCount_1`）と「9」の個数（`UserInputCount_2`）を記録します。
* **⚠️ Performanceの向き**：UIでは「高スコア＝上手にできた」に反転しています。総合ワークロード（RTLX）を算出する際は、`10 - Performance` に戻してから他の5尺度と合算してください。

### ⑤ `presurvey_{ID}.csv`（事前アンケート）
| 列 | 内容 | 値 |
|---|---|---|
| Age | 年齢 | 数値 |
| Gender | 性別 | 0=男, 1=女, 2=回答しない |
| Language | 第一言語 | 自由記述 |
| SleepSufficient | 昨晩の睡眠の十分度 | 1（不十分）〜5（十分） |
| SleepHours | 昨晩の睡眠時間 | 時間 |
| Condition | 現在の体調 | 1（非常に悪い）〜5（非常に良い） |
| Stress | 現在の気分やストレス | 0（非常にリラックス）〜10（非常にストレス） |
| TouchTyping | タッチタイピングができるか | 0=はい, 1=いいえ, 2=ある程度 |
| Keyboard | 普段使うキーボード | 0=ノートパソコン, 1=デスクトップ用 |
| Caffeine | 過去4時間以内のカフェイン摂取 | 0=はい, 1=いいえ |

### ⑥ `postsurvey_{ID}.csv`（事後アンケート）
実験全体についての自由記述です。任意回答のため、未記入の場合はファイルが作成されません。

## 5. トラブルシューティング（よくあるエラーと解決法）

#### Q. Polar中継器で `[WARNING] 有効なPPIが取得できません` と出続ける
センサーが肌に密着しておらず、脈波を捉えられていません。デバイスの裏面の緑色のLEDが光っているか確認し、光学面が肌に直接当たるようにテープで胸部に圧着し直してください（Step 1参照）。

#### Q. Polar中継器で `Characteristic ... was not found!` というエラーが出る
PCのBluetoothが、Polarデバイスの特殊なデータ送信機能（PMD）を見失っています。次の手順で解決します。
1. WindowsのBluetooth設定から「Polar Sense XXXX」を削除（ペアリング解除）する
2. PCのBluetoothを一度オフにしてオンにする
3. 再度ペアリングし直す

#### Q. メインアプリで「LSLストリームが見つかりません」と出る
`polar_to_lsl.py`（または `lsl_mock.py`）が起動していないか、ストリーム名が異なっています。必ず**メインアプリを起動する前に**、中継器を起動しておいてください。

#### Q. 長時間タイピングしたのに、キーのデータが少ししか保存されていない
タイピング中に被験者がマウス等で別の場所をクリックし、入力欄（テキストボックス）から**フォーカスが外れてしまった**可能性があります。現行バージョンではフォーカス強制処理を入れていますが、実験中は被験者に「マウスは触らずタイピングに集中してください」と指示してください。

- **プロトコルの9パターン化**：負荷条件と文章（A/B/C）の組合せを入れ替える9パターンのラテン方格に変更しました。文章内容へのショートカット学習を抑え、文章IDを要因として扱えるようにするためです。

- **心拍データへのフェーズ列の追加**：`heartrate_{ID}.csv` に受信時点のフェーズ（`Current_Phase`）を記録するようにしました。
- **待機画面の視覚負荷軽減**：`Cross View` の背景をダークグレー（`#1A1A1A`）に変更し、中央の十字マークを廃止して「リラックスしてお待ちください」という控えめなテキスト表示のみにしました。
- **主観評価UIの改善**：NASA-TLXの入力方法を0〜100のスライダー式から、0〜10の11段階（ラジオボタン）に変更し、マウス操作による運動負荷を排除しました。

- **高負荷タスクのカウント入力の分離**：「1」と「9」のカウントを、合計値ではなくそれぞれ別の入力欄で回答・記録するようにしました（`UserInputCount_1`, `UserInputCount_2`）。

- **タイトルバーのダークモード化**：Windows環境でOSのタイトルバーが白く浮かないよう、ダークモード化する処理を追加しました（`config.FULLSCREEN = True` にすると完全なフルスクリーンも可能です）。
